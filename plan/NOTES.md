# Notes: quirks and suspected bugs found while porting (do not fix; record)

- api.php product routes outside auth groups were unauthenticated in the old app; new app guards them (roles admin,user,remote). Intentional.
- api.php routes duplicated in web.php are shadowed (web wins); only the web.php version is ported.
- /OrderHistory, /SaveOrder, /UpdateShippedOrder, /ProcessOrders point at non-existent controllers; not ported.
- (T03) The old app has no resources/views/errors/404 view, so with APP_DEBUG=true (its .env) a 404 renders Symfony's detailed debug exception page (PHP traces, request meta). The new app serves the production (non-debug) Symfony 404 page: `<h1>404 | Not Found</h1>` + "Whoops, looks like something went wrong." 404 bodies are therefore not asserted in parity.
- (T03) Laravel 5.4 paginate() JSON has no first_page_url/links keys, and `from` goes negative (e.g. -14 for per_page 15) when total is 0. Ported as-is.
- (T04) DatatablesEditor::process "create" action on an Eloquent Builder crashes in the old app (`$model[0]->create()` where $model is a single Model instance → `null->create()` fatal). Ported to throw (500) with the same message. The string/table path of the same method is only used by a commented-out test in the old app.
- (T04) maatwebsite/excel 2.1 returns PHPExcel DateTime objects for date cells; Laravel JSON encodes them as ISO-8601 with microseconds and offset. src/excel.ts emits `toISOString()` (Z, no microseconds). Only affects the two picklist upload routes (Tongtool/Wayfair), which are not parity-tested.
- (T04) yajra v6 `extractColumnName` strips `table.` prefixes from column names before search/order (search is then unqualified). Ported; matters only when a query joins.
- (T10) `HomeController@report` (/report, role:admin) and six of the seven `Route::resource('Settings')` actions (create/store/show/edit/update/destroy) point at methods that do not exist in the old controllers, so the old app 500s on them (BadMethodCallException). New app renders the old app's own `resources/views/error/500.blade.php` port (`views/error/500.njk` via `sendServer500` in src/view.ts) — same pattern as the T02 /api/settings/* and /register quirks.
- (T10) Laravel `route()`/`URL::route()` emits ABSOLUTE URLs (RouteUrlGenerator prefixes the request root), not relative ones. T01's `route()` global was relative; it now returns `url(routeUrl(...))`. Also: shared layouts call `route()` for every module's named routes, so `preloadRouteTable()` (src/router.ts, called from server.ts) pre-seeds the named-route table from plan/inventory.json plus the synthesized `<base>.<action>` names of the 16 `Route::resource` calls in web.php (they carry no `as` name, so the inventory lacks them). Modules' own registerRoute() calls overwrite these at startup; explicit `as` names (e.g. `opolo.index`) win over resource names, matching Laravel's later-registration-wins.
- (T11) `TimesheetController@index` (/timesheet, Route::any, role:admin) always 500s in the old app: it calls `$request->user()->company()`, and `User::company()` (namespace `App`) does `Company::where(...)`, which resolves to the non-existent `App\Company` (the model is `App\Models\Company`). New app reproduces the 500 via `sendServer500` (same pattern as T10's missing-method 500s); the ported `views/timesheet/index.njk` is never reached. /timesheet is therefore excluded from T11's parity list (the old app's APP_DEBUG Symfony 500 page is not reproducible, as in T03/T10).
- (T11) `StaffsController` store/update/destroy flash `flash_message` (the layout reads success/error/warning/info, never `flash_message`) and `redirect('admin/staffs')` — a path with no route (the resource lives at `/staffs`). Both reproduced as-is, so a staff create/update/delete 302s to a 404 in both apps.
- (T12) Every `PriceController` action (/price, /price.ajax, /price.getRequest.ajax) fatals in the old app with `Class 'BaseController' not found` (the controller extends a non-existent global `\BaseController`; also its `CustomerRequest` model points at a `cart` connection that does not exist in config/database.php). New app reproduces the 500 via `sendServer500`; `views/price/index.njk` is ported but, like the old app, never rendered. /price and /price.ajax are excluded from T12's parity list (old app's APP_DEBUG Symfony 500 page is not reproducible, as in T03/T10/T11).
- (T12) /exec.run and /exec.refreshAmz (role:admin[,user,remote]) execute whatever artisan command an admin types into a form — a backdoor in the old app. Ported to the `artisanCall()` registry (src/jobs/artisan.ts); the old app's commands (Runner `sync`, Mover, ...) are registered in Phase 5 (J1-J6). Unknown command -> 500 `Command "x" is not defined.` (Laravel's message). Until Phase 5, /exec.run 500s for every command and /exec.refreshAmz 500s for every ASIN.
- (T12) /queue.ping pushes a QueuePing job onto the old app's queue (QUEUE_CONNECTION=database); the job inserts an os_queuejobs row (type=ping) and fires QueuePingEvent, which has no listeners. New app runs it inline (same observable row + 302 to /queue).
- (T12) /queue.print: `$is_pdf` is never set true in the PHP, so the `queuejob/pdf` view is dead code; `views/queuejob/pdf.njk` is ported but never rendered. Unknown/missing queueId returns an empty 200 body (Laravel `return null`).
