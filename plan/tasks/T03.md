# T03 — Router helpers + parity harness

Phase: 0. Depends on: T02.

Read `plan/CONVENTIONS.md` and `plan/PLAN.md` first. Old app: `~/code/office` (read-only). Work in `~/code/office_new`.

## Instructions

1. `src/router.ts`: `route(app, {verb, path, name, roles?, middleware?, handler})` where verb ∈ get|post|put|patch|delete|any;
   `resource(app, base, handlers, {roles, names})` (Laravel resource: index GET base, create GET base/create, store POST base,
   show GET base/{id}, edit GET base/{id}/edit, update PUT|PATCH base/{id}, destroy DELETE base/{id}; parameter name is
   the singular of base). Support `_method` spoofing: for POST requests whose body has `_method`, dispatch to the PUT/PATCH/DELETE
   handler (register POST base/:id for that). Optional params `{id?}` → register both variants. Laravel `{x}` → `:x`.
   Keep a named-route registry; `routeUrl(name, params)` builds absolute URLs like Laravel `route()` (extra params → query string).
   Wire `route()` in view.ts to it.
2. Not-found fallback (`setNotFoundHandler`): replicate Laravel's regex catch-alls in original order (see
   `plan/inventory.json` routes with `where` set): `/{Supplier?}` where `[\/Supplier\.-]*` (roles admin,user,supplier) →
   SupplierProduct@index; then `/{ListProducts?}`, `/{InventoryCount?}`, `/{InventoryConsolidation?}`, `/{Orders?}` (roles
   admin,user,remote) → Product@vue. Handlers are registered later by T26/T30 via `registerFallback(name, handler)`;
   until then return Laravel's 404 page. Unmatched → Laravel 404 view (`views/errors/404.njk` if it exists, else Laravel's default).
3. `src/http.ts`: input(req,k), allInput(req), redirectBack(req, reply) (uses Referer like Laravel), withErrors, withInput,
   paginate(query, perPage, req) returning Laravel 5.4 LengthAwarePaginator JSON shape.
4. `scripts/parity.ts`: `pnpm parity --task T10` reads `plan/parity-routes.json[T10]`; or `--urls /a,/b`. Logs into OLD_APP_URL
   (GET /login → read `_token` + laravel_session cookie → POST /login) and the new app (POST /login) with
   PARITY_EMAIL/PARITY_PASSWORD; fetches each URL from both with `redirect: 'manual'`; compares status, Location header,
   and body. HTML normalize: collapse whitespace, strip `_token` values / csrf meta, strip APP_URL host differences
   (old vs new base URL), strip `?id=<mix hash>`. JSON: deep-equal after parse. Prints a unified diff (first 80 lines) per
   failing URL; exit 1 if any fail. Also writes full outputs to `.parity/<task>/`.
5. Start the old app if it isn't running: document the exact docker command in `plan/RUNBOOK.md` (from
   `~/code/office/docker-run-readme.md`; MySQL and Redis are docker containers `mysql` and `redis` on network `stack_default`).
Verify: `pnpm parity --urls /home,/login` passes (after logging in both).
