# J1 — Scheduler + queue infrastructure

Phase: 5. Depends on: T00, T01, T02, T03, T04.

Read `plan/CONVENTIONS.md` and `plan/PLAN.md` first. Old app: `~/code/office` (read-only). Work in `~/code/office_new`.

## Instructions

1. BullMQ on existing Redis, queue prefix `office_new` (must not collide with Laravel's queue keys).
2. `src/jobs/scheduler.ts`: register repeatable jobs mirroring every **uncommented** `$schedule->command(...)` in
   `~/code/office/app/Console/Kernel.php` (same cron expressions, same timezone). Only registers when SCHEDULER_ENABLED=1.
3. `src/jobs/worker.ts` process + `pnpm worker` script; `pnpm sync <action> [arg1]` CLI equivalent to `php artisan sync`.
4. Port `app/Jobs/*` (MassPrintLabel, AmzMassPrintLabel, FrayunMassPrintLabel, DownloadLabel, QueuePing) as BullMQ jobs, and
   wire their dispatch sites (grep `dispatch(` / `Queue::push`) in already-ported modules. QueueJob pages (T12) must show the new queue's state the same way.
5. Port `PdaApiKeyCommand` and `FaireImportImages` commands as `pnpm` scripts.
Action handlers themselves are J2–J6; register them via a `actions` map, unknown action → same error text as Runner.php.
