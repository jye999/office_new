# T04 — Shared helpers: DataTables, Pusher, mail, storage, excel

Phase: 0. Depends on: T03.

Read `plan/CONVENTIONS.md` and `plan/PLAN.md` first. Old app: `~/code/office` (read-only). Work in `~/code/office_new`.

## Instructions

Only build what modules need; each helper gets a unit test.
1. `src/datatables.ts`: yajra/laravel-datatables-oracle **v6** server-side protocol for a Kysely query: read draw, start,
   length, search[value], order[i][column|dir], columns[i][data|name|searchable|orderable]; global search = OR LIKE
   %v% over searchable columns; per-column search; response `{draw, recordsTotal, recordsFiltered, data}` with the same
   key order and types as yajra v6. Support `editColumn`/`addColumn` callbacks. Read the yajra v6 source in
   `~/code/office/vendor/yajra` to match edge cases (e.g. length -1 = all).
   Also port `app/Libraries/DatatablesEditor.php` if it's used by Inventory (check) → `src/lib/datatables-editor.ts`.
2. `src/pusher.ts`: thin wrapper reading PUSHER_* (copy names from old .env) — `trigger(channel, event, data)`.
3. `src/mail.ts`: nodemailer from MAIL_* env, **no-op + log unless MAIL_ENABLED=1**.
4. `src/storage.ts`: local disk (PUBLIC_DIR, storage path) + S3 (@aws-sdk/client-s3) mirroring `config/filesystems.php` disks used by the app.
5. `src/excel.ts`: exceljs helpers to produce xlsx/csv downloads matching maatwebsite/excel 2.1 output used by the app
   (grep `Excel::create` / `Excel::load` to see which features are used).
6. `src/images.ts`: sharp-based equivalents of the Intervention calls used (grep `Image::make`).
